# خطة إعادة هيكلة الواجهة وسجل الاستئناف

> هذا الملف هو المرجع الوحيد لمعرفة أين توقف العمل. يُحدَّث مع كل التزام.
> القاعدة: لا تُعلَّم خطوة «تم» إلا بعد دفعها إلى الفرع. ولا تُعلَّم «مُتحقَّق» إلا بعد تشغيلها فعليًا.

## الهدف
تقسيم `Sahm_Preview_ROLE_SEPARATION.html` إلى شجرة ملفات صغيرة، وربط كل الشاشات بـ `SahmApp` (ثم `SahmData`/`SahmCore`)، وإزالة `localGroups` ومصادر `db` القديمة والشاشات التجريبية التي لا يعتمدها المرجع V2.

## قيود ثابتة
- الشاشة الرئيسية والشريط العلوي (الثابت والديناميكي) تُنقل **حرفيًا**: لا تغيير في التصميم أو الألوان أو الخطوط أو الأحجام أو الأيقونات أو المسافات أو السلوك.
- لا إعادة بناء للمحرك أو طبقة البيانات، ولا منطق موازٍ لهما. الشاشات لا تحسب مبالغ ولا حالات ولا أهلية قرعة.
- الاختبارات الحالية كما هي، بلا اختبارات جديدة في هذه المرحلة.
- لا دمج إلى `main` ولا نشر. العمل على `feature/sahm-final-preview-product` فقط.
- لا يُحذف شيء معتمد في المرجع V2 أو أي بيانات.

## الشجرة المستهدفة
```
index.html                 هيكل الصفحة وتحميل الملفات
styles/ base.css · shell.css · screens.css
sahm-core.js · sahm-data.js          (تبقى مكانها)
src/
  app.js                   SahmApp: نقطة الربط الوحيدة بالبيانات (موجود كملف sahm-app.js، ينقل إلى src/ عند الاستقرار)
  ui.js                    أيقونات، تنبيه، نافذة، تنسيق
  router.js                التنقل والرجوع وتسجيل الشاشات
  screens/ home · groups · group-create · members · installments · draw · chat · account
  main.js                  الأحداث والإقلاع
```

## آلية العمل
1. سكربتات عادية بلا أداة بناء وبلا `import`. كل ملف يكشف كائنه على `window` (مثل `SahmApp`) أو يسجّل شاشته في `router.js`. تعمل في المتصفح كما هي، وتصلح لاحقًا لـ Capacitor/APK أو التحويل إلى وحدات ES.
2. ترتيب التحميل في `index.html`: core ← data ← app ← ui ← router ← screens ← main.
3. الشاشات لا تلمس التخزين ولا `SahmData` مباشرة. تمرّ عبر `SahmApp` فقط، فيتغير ملف واحد عند الانتقال إلى قاعدة بيانات حقيقية.
4. كل شاشة: تقرأ من استعلامات `SahmApp`، وتنفّذ عبر عملياته، وتعرض `message` عند `ok:false` وتحذير الحفظ عند `persisted:false`، وتقرأ الصلاحيات من `groupDetail().permissions` لا من إخفاء الأزرار فقط.
5. الأنماط والشاشتان المعتمدتان تُنسخ حرفيًا من الملف القديم دون إعادة صياغة.
6. الملف القديم يبقى مرجعًا ويظل يعمل حتى تعمل الشجرة الجديدة، ثم يُحذف بعد المراجعة.
7. كل دفعة تُدفع بالتزام مستقل ورسالة واضحة، ثم يُحدَّث هذا السجل في التزام تالٍ أو معه.
8. توثيق مختصر للدفعات الصغيرة، وأوضح عند اكتمال دفعة كبيرة.

## قرارات مفتوحة
- مصير بيانات `prefs.localGroups` الموجودة: تُؤرشف قبل الإزالة؛ نموذجها لا يحمل نوع الدورة وعدد الأقساط فلا يمكن تحويلها بدقة إلى `createGroup`.
- بنود عقد البيانات المرجأة (تجاوز النصاب، التسجيل المسبق، تغيير الإعدادات بعد بدء الدورات): لا تظهر في الواجهة حتى تُحسم.
