# خطة إعادة هيكلة الواجهة وسجل الاستئناف

> المرجع الوحيد لمعرفة أين توقف العمل، ويُحدَّث مع كل التزام.
> «تم» = دُفع إلى الفرع. «مُتحقَّق» = شُغّل فعليًا.

## الهدف
تقسيم `Sahm_Preview_ROLE_SEPARATION.html` إلى شجرة ملفات صغيرة، وربط كل الشاشات بـ `SahmApp` ثم `SahmData`/`SahmCore`، وإزالة `localGroups` ومصادر `db` القديمة والشاشات التجريبية التي لا يعتمدها المرجع V2.

## قيود ثابتة
- **المعتمد بصريًا وسلوكيًا شيئان فقط:** الشاشة الرئيسية والشريط العلوي (الثابت والديناميكي). يبقيان بلا أي تغيير في التصميم أو الألوان أو الخطوط أو الأحجام أو الأيقونات أو المسافات أو السلوك.
- بقية الشاشات تُراجع وتُنظَّم وفق المرجع V2، وتُزال أو تُعدَّل قواعدها القديمة المتعارضة.
- لا إعادة بناء للمحرك أو طبقة البيانات، ولا منطق موازٍ. الشاشات لا تحسب مبالغ ولا حالات ولا أهلية قرعة.
- الاختبارات الحالية كما هي، بلا اختبارات جديدة. لا دمج إلى `main` ولا نشر.
- لا يُحذف شيء معتمد في V2 ولا أي بيانات.

## سياسة الـ CSS (تحكم الخطوة 2)
الـ CSS الحالي نحو 92 ألف حرف و825 مجموعة محددات و32 قاعدة `@media/@keyframes`. **لا يُنقل حرفيًا كله.**
1. **تصنيف أولًا:** كل قاعدة تُصنَّف إلى (أ) محمية: الرئيسية والشريط العلوي والعناصر التي يعتمدان عليها، (ب) مشتركة وعامة، (ج) خاصة بشاشة أخرى.
2. **المحمية** تُنقل حرفيًا إلى `styles/shell.css`، بما فيها المتغيرات والـ `@media` والحركات الخاصة بها.
3. **المشتركة والعامة** (`body`, `button`, `input`, `.btn`, `.pill`, `.card`, `.field`, `.listrow`, `.avatar`, `.row`, `.between`, `.segmented`, `.toolbar`, `.empty`, `.dialog`, `.toast` وغيرها): لا تُعدَّل قبل رصد استخدام الشاشتين المحميتين لها. ما تستخدمه المحميتان يبقى حرفيًا في `base.css` أو `shell.css`. وأي تنظيم لاحق لها يمر عبر **قواعد مقيّدة بنطاق الشاشة** (مثل `.screen-x .btn`) لا عبر تعديل القاعدة العامة.
4. **الخاصة بالشاشات الأخرى** تُراجع وتُكتب من جديد في `screens.css` وفق V2، وتُحذف القواعد اليتيمة (التي لا يستخدمها أي ترميز بعد إعادة البناء) وتلك الخاصة بالشاشات الملغاة.
5. **ضمان الحماية:** يُسجَّل في هذا الملف جدول بالقواعد العامة التي تستخدمها المحميتان، ولا يُعدَّل أي منها إلا بقرار صريح. ترتيب التحميل: `base.css` ← `shell.css` ← `screens.css`، ولا تُعاد كتابة محددات `shell.css` داخل `screens.css`.
6. **حدود التحقق:** لا أستطيع هنا عرض الصفحة. المقارنة البصرية للمحميتين قبل/بعد تحتاج متصفحًا، وتُسجَّل كخطوة تحقق معلقة حتى تتم.

## آلية العمل
1. سكربتات عادية بلا أداة بناء وبلا `import`. ترتيب التحميل: core ← data ← app ← ui ← router ← screens ← main.
2. الشاشات لا تلمس التخزين ولا `SahmData` مباشرة؛ كلها عبر `SahmApp`.
3. كل شاشة تعرض `message` عند `ok:false` وتحذير الحفظ عند `persisted:false`، وتقرأ الصلاحيات من `groupDetail().permissions`.
4. الملف القديم يبقى مرجعًا ويعمل حتى تعمل الشجرة الجديدة، ثم يُحذف بعد المراجعة.
5. التزام مستقل لكل دفعة، وتحديث هذا السجل معه. توثيق مختصر للصغيرة وأوضح للكبيرة.
