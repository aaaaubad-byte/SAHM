# دليل إعداد Supabase لمشروع سهم

## المشروع المستهدف

- الاسم: SAHM
- Project ref: `nusjnnrtpxbpphphmdsc`
- URL: `https://nusjnnrtpxbpphphmdsc.supabase.co`
- المنطقة: `ap-northeast-1`
- PostgreSQL: 17.x
- الواجهة المنشورة: `https://sahm-supabase-preview-fixed.onrender.com`

## إعدادات Auth المطلوبة قبل اعتماد التسجيل

إعدادات Auth الإدارية لا تتوفر للقراءة أو التعديل عبر أدوات الإدارة المستخدمة في هذا التنفيذ؛ يجب مراجعتها من Supabase Dashboard:

1. افتح **Authentication → URL Configuration**.
2. عيّن **Site URL** إلى:
   `https://sahm-supabase-preview-fixed.onrender.com`
3. أضف إلى **Redirect URLs**:
   `https://sahm-supabase-preview-fixed.onrender.com/**`
   حتى تعمل روابط تأكيد البريد واستعادة كلمة المرور على نطاق المعاينة.
4. وثيقة المشروع السابقة تسجل رغبة المالك في تعطيل **Confirm Email** لتكون رحلة التسجيل مباشرة إلى إكمال البيانات الشخصية. تحقق من هذا الإعداد يدويًا؛ لم أغيّره ولم أتمكن من قراءة حالته عبر الأدوات.
5. اترك **Phone provider / SMS / Phone OTP** غير مفعّل؛ الهاتف هنا بيانات ملف شخصي وليس وسيلة دخول أو إثبات ملكية.
6. من **Authentication → Settings → Password Security** فعّل **Leaked Password Protection**. أظهر Security Advisor تحذيرًا واحدًا لأن هذه الحماية معطلة حاليًا.

## إعداد عميل المتصفح

- خدمة Render من نوع Static Site ولا تحقن Environment Variables تلقائيًا داخل JavaScript.
- ملف `sahm-supabase.js` يحتوي حاليًا على Project URL ومفتاح `publishable` العام فقط.
- لا يوجد في ملفات المتصفح أي مفتاح `service_role` أو Secret key. لا تضفها أبدًا إلى HTML أو JavaScript أو GitHub.
- إذا تغير المشروع لاحقًا، حدّث URL ومفتاح publishable في ملف العميل واختبارات التهيئة معًا.

## التسجيل وإكمال الملف الشخصي

1. شاشة الدخول تستخدم البريد الإلكتروني وكلمة المرور.
2. شاشة إنشاء الحساب تستخدم البريد وكلمة المرور وتأكيدها، وتتطلب موافقة صريحة على الشروط وإصدارها.
3. يستدعي العميل `auth.signUp` مع metadata لموافقة الشروط فقط.
4. Trigger على `auth.users` ينشئ `profiles` و`profile_private` و`user_preferences` داخل المعاملة نفسها.
5. بعد إنشاء الحساب وتوفر جلسة صالحة، ينتقل المستخدم إلى شاشة البيانات الشخصية:
   - الاسم الكامل من ثلاثة مقاطع على الأقل.
   - رقم الهاتف مع اختيار الدولة، واليمن هي الافتراضية.
   - أيقونة جاهزة من مجموعة رموز؛ لا يوجد رفع صور ولا حاجة إلى Storage.
6. يحفظ العميل الاسم والهاتف والأيقونة عبر `complete_my_profile`، وتتحقق قاعدة البيانات من الاسم وصيغة E.164 وتفرّد رقم الهاتف.
7. لا ينتقل المستخدم إلى الرئيسية إلا بعد نجاح حفظ الملف الشخصي.

إذا كان Confirm Email مفعّلًا، يجب على المستخدم تأكيد بريده أولًا ثم العودة إلى التطبيق؛ بعد استعادة الجلسة سيظهر له إكمال الملف الشخصي. إذا كان معطلًا، ينتقل مباشرة بعد نجاح التسجيل.

## تسجيل الدخول واستعادة كلمة المرور

- الدخول: `supabase.auth.signInWithPassword({ email, password })`.
- استعادة: `supabase.auth.resetPasswordForEmail(email, { redirectTo })`.
- استعادة الجلسة: يقرأ العميل جلسة Supabase ويعيد تحميل بيانات الجمعيات من قاعدة البيانات.
- عمليات الإنشاء والتعديل والاستلام والتصحيح والقرعة لا تعرض نجاحًا قبل استجابة RPC خادمية ناجحة.

## قاعدة البيانات الحالية

- 23 جدولًا في `public`، وكلها مفعّل عليها RLS.
- 31 سياسة RLS.
- 12 migration مسجلة.
- 5 اختبارات SQL ناجحة على المشروع الفعلي: سلامة المخطط، RPC، مصادقة البريد والملف، تسجيل/إكمال الملف، وسير الجمعية/الدعوة/الأسهم. اختبارات الدخان التي تنشئ مستخدمين أو جمعيات تستخدم `ROLLBACK`.
- البيانات التشغيلية الموجودة حُفظت؛ لا تُشغّل `resetAll` أو أي تنظيف عام على المشروع.

## إعداد Realtime وStorage

- Realtime مفعّل للمحادثات والبيانات الحية التي تحتاجها الواجهة. لا تستخدم Realtime لتنفيذ القرعة أو الأقساط أو الاستلام؛ هذه عمليات RPC ذرية.
- لا توجد حاويات Storage؛ لا حاجة لصور شخصية أو مرفقات في نموذج V2 الحالي.

## اختبارات المشروع

تشغيل اختبارات JavaScript:

```bash
node --test tests/*.test.js
```

آخر نتيجة موثقة: 64/64 اختبارًا ناجحًا على GitHub Actions، دون إخفاقات.

## ما يلزم قبل إطلاق الإنتاج

- تأكيد Site URL وRedirect URLs وConfirm Email من لوحة Supabase.
- تفعيل Leaked Password Protection وإعادة تشغيل Security Advisor.
- تجربة فعلية بصندوق بريد حقيقي لتأكيد البريد والدخول واستعادة كلمة المرور.
- تجربة الواجهة في Chrome على هاتف فعلي؛ اختبارات Node وفحوص SQL لا تستبدل اختبار المتصفح الحي.
- مراجعة قانونية لنص الشروط والأحكام قبل اعتماده تجاريًا.
