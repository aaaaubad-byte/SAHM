# تقدّم الدفعة الثالثة (ربط الواجهة) — ملف الاستئناف

## أُنجز
- `sahm-app.js`: مسار الربط الموحد `SahmApp`. يحمل نسخة المخزن الوحيدة ومعرّف المستخدم الحالي، ويمرر `(db, viewer)` تلقائيًا لكل عملية واستعلام في `SahmData`، ويبلغ عن الرفض أو تعذر الحفظ عبر `onResult`. لا يحتوي أي قاعدة حساب أو أهلية أو صلاحية. تم الدفع إلى الفرع.

## لم يُنجز بعد (لم يُربط ولم يُتحقق منه)
- لم يُعدَّل `Sahm_Preview_ROLE_SEPARATION.html` بعد؛ لا يوجد حتى الآن تحميل لـ `sahm-app.js` فيه، ولا استبدال لـ `localGroups` أو `db.groups` المشتق في `syncFromStore`.
- الشاشات التي ما زالت على المصدر القديم: إنشاء الجمعية (`createGroup` في الواجهة)، تفاصيل الجمعية، الأعضاء، الدعوات، الأقساط وتسجيل المدفوع، القرعة، الإيصالات، الحائط/المحادثة، التنبيهات، وسجل العمليات.
- مسارات قديمة يجب إزالتها: `paymentSubmit`، `review`، `selectedPayment`، `db.payments`، `createReceipt`، `entitlements`، `member-vote`، واعتماد `localGroups`.
- لا يوجد ترحيل لبيانات `prefs.localGroups` الموجودة؛ تُؤرشف قبل الإزالة (قرار مفتوح: نموذجها لا يحمل نوع الدورة وعدد الأقساط).

## عائق تنفيذي
أداة الكتابة المتاحة تستبدل الملف كاملًا ولا تدعم تعديلًا جزئيًا. ملف الواجهة نحو 190 ألف حرف، فلا يمكن تعديله في خطوة واحدة دون مخاطرة بالتغيير البصري للشاشة الرئيسية والشريط العلوي المعتمدين.

## خطة الاستئناف
1. تقسيم سكربت الواجهة (السطور 3238–3801) إلى ملفات خارجية تُكتب على دفعات صغيرة، مع إبقاء CSS وبنية الشاشة الرئيسية والشريط العلوي كما هي حرفيًا.
2. استبدال `load/syncFromStore/save` بـ `SahmApp`، ثم ربط الشاشات بالترتيب: الجمعيات والتفاصيل، الإنشاء، الأعضاء والدعوات، الأقساط، القرعة، المحادثة والتنبيهات.
3. حذف المسارات القديمة المذكورة أعلاه بعد ربط بدائلها.
